# ViBilet — 画面仕様書（公開版）

> 本書は、ViBilet初期版のUI設計方針、ユーザー体験、主要画面の役割および画面遷移をまとめた公開用資料です。詳細な実装仕様をすべて定義するものではありません。開発中の機能や演出は、今後変更される可能性があります。

## 1. 文書概要

本書は、デジタル生命体育成アプリ **ViBilet** のUI/UX設計方針、主要画面、画面遷移、およびゲームロジックとの責務分離を説明する公開用資料である。

本書は非公開の詳細画面仕様書を要約したものであり、すべての操作条件、数値閾値、演出フレーム、未確定事項は掲載しない。

## 2. デザイン方針

### 2.1 LIFEを主役にする

HOMEは操作メニューではなく、**LIFEがデジタル空間で自律的に生活する場所**として設計する。ユーザーはLIFEの動作や反応を観察し、必要に応じて近づき、交流する。

- 暗いデジタル空間、グリッド、データ粒子を基本とする。
- ドット絵のLIFEとその行動を画面の中心に置く。
- 常設HUDは最小限に抑え、詳細情報は別画面へ集約する。
- 数値だけでなく、外見、行動、ノイズ、表示変化によって状態を伝える。

### 2.2 同じLIFEが成長する体験

成長は別のキャラクターへの交換ではなく、**同じLIFEが新たな形態を獲得する変化**として演出する。名前、経過時間、育成の連続性を維持する。

```text
EGG → PIX → JUVENILE → ADULT
              │
              └─ BLAZE / FLOW / BLOOM
```

成長系統の選択とPATCH演出は、デジタル生命体という世界観に沿って設計する。

## 3. 主要画面

| 画面 | 目的 | 主な体験 |
|---|---|---|
| STARTUP | LIFEとの接続を開始する | 接続・データ読み込みの演出 |
| NEW LIFE / EGG | 新しい生命との出会い | 共通EGGから育成を開始 |
| HATCH | LIFEの誕生を表現する | EGGからPIXが現れる |
| NAMING | 個体に名前を付ける | 誕生したLIFEを見ながら命名 |
| HOME | LIFEの生活を観察する | 自律行動、経過日数、状態の視覚表現 |
| INTERACTION | LIFEと交流する | FOOD、TOUCH、PLAY（内容は開発中） |
| LIFE DATA | 個体情報を確認する | 名前、年齢、状態、関係性など |
| PATCH | 成長の節目を表現する | 系統選択、確認、形態変化 |
| LIFE END / MEMORY DATA | 生涯の終わりと次世代を扱う | 終了演出、記録、次世代への接続 |

一部の画面や演出は設計・制作段階であり、現時点ですべてが完成していることを意味しない。

## 4. 全体画面遷移

以下は代表的なユーザーフローを示す。例外的な再開処理や細かな判定分岐は省略する。

```text
STARTUP
   │
   ├─ 既存のLIFE ───────────────────────┐
   │                                   │
   └─ NEW LIFE → EGG → HATCH → NAMING  │
                                       ▼
                                      HOME
                                    /      \
                                   ▼        ▼
                             INTERACTION  LIFE DATA
                                   \        /
                                    └── HOME
                                         │
                                  Growth PATCH
                                         │
                              JUVENILE / ADULT
                                         │
                                        HOME
                                         │
                                      LIFE END
                                         │
                                     MEMORY DATA
                                         │
                                      NEW LIFE
```

起動時には保存されたLIFEの状態を確認し、通常のHOME、未完了の成長イベント、生命活動終了処理など、適切な体験へ案内する設計とする。

## 5. コア画面のUX

### 5.1 HOME — 観察のための空間

HOMEではLIFEが歩く、止まる、眠るなどの行動を取る。ユーザー操作を常時要求するのではなく、生活の様子を見守れる構成を目指す。

- **DAY**：誕生からの経過日数を簡潔に示す。
- **DATA**：LIFE DATAへの導線。
- **LIFEへのタップ**：交流画面への移動を開始する。
- **JUNK DATA**：デジタル空間の状態を視覚的に示す。

詳細な育成パラメータや残り寿命をHOMEに常設しない。

### 5.2 INTERACTION — LIFEとの距離を縮める

HOMEのLIFEに触れると、LIFEがユーザーへ近づくような遷移を経て交流画面へ移る。単なる画面切替ではなく、**LIFEがこちらに応じた**と感じられる体験を重視する。

交流操作はFOOD、TOUCH、PLAYを基本とする。操作に応じてLIFEがリアクションし、関係性や育成状態に反映される。PLAYの具体的な内容は開発中である。

### 5.3 LIFE DATA — 情報を必要なときに確認する

LIFE DATAには、個体のプロフィールと現在状態をまとめる。

| 項目 | 内容 |
|---|---|
| NAME / SPECIES | 名前・現在の形態 |
| AGE | 誕生からの経過時間 |
| LIFE RHYTHM / PERSONALITY | 生活リズム・性格 |
| CONDITION | 現在の状態 |
| BOND / SATIETY | 関係性・満腹状態 |
| MEMO | LIFEの特徴を表す短い文章 |

内部パラメータをすべて数値表示するのではなく、ユーザーにとって意味のある情報に変換して提示する。寿命の残り時間は直接表示しない。

## 6. ライフサイクルの体験設計

### 6.1 誕生

共通EGGからPIXが生まれ、ユーザーが名前を付ける。誕生した存在を命名画面でも継続して表示し、**いま出会った個体に名前を与える**体験を重視する。

### 6.2 成長とPATCH

LIFEは時間の経過と育成の結果に応じて成長する。PATCHは、生命体に新たなデータが適用され、姿を獲得する世界観上の表現である。

成長系統には **BLAZE / FLOW / BLOOM** を用いる。成長後も同一個体としての連続性を保つ。

### 6.3 生命活動の終了と次世代

LIFEには寿命があり、生涯の終了は育成体験の一部として扱う。終了後はデータ分解やMEMORY DATAの演出を通じて、その個体の記録と次世代へのつながりを表現する。

継承は前世代をそのまま復元する仕組みではなく、**面影を次のLIFEへ残す**ことを目指す。

## 7. 状態を伝える視覚表現

ViBiletでは、LIFEの状態を数値だけで説明しない。

- **行動・表情**：空腹、眠気、親密さなどを反応として伝える。
- **JUNK DATA**：不要データをデジタル空間内のオブジェクトとして可視化する。
- **表示破損**：蓄積状態に応じてノイズ、文字化け、キャラクター表示の乱れなどを段階的に表現する。
- **PATCH演出**：データの変換・再構成として成長を表現する。

表示破損は原則として**演出上の変化**であり、保存済みの個体情報そのものを破損させない。また、必要なナビゲーションや操作の可読性を維持する。

## 8. UIとゲームロジックの責務分離

画面上の一時的な表現と、LIFEの継続的な状態を区別する。

| UI・演出に属するもの | ゲーム状態に属するもの |
|---|---|
| 表示位置、向き、アニメーションフレーム | Hunger、Bond、Care |
| タップ時の一時的なリアクション | Lifetime、Age、Life Status |
| ノイズ、粒子、画面遷移エフェクト | JUNK DATA、DATA ERROR |
| 画面上の拡大縮小・表示制御 | 成長段階、PATCH状態、MEMORY DATA |

DAYなどの表示情報は、ゲーム状態から導出することを基本とする。UIの見た目を変更しても、生命体の内部状態やゲームルールへ不要な影響を与えない構造を目指す。
