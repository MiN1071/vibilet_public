# 2. アプリ概要

## 2.1 コンセプト

**出会いと別れを繰り返しながら、受け継いでいくデジタルペット**

ViBiletは、スマートフォンの中で暮らす「デジタル生命体」を育てるアプリである。

生命体は現実世界の時間と連動して生活し、ユーザーがアプリを操作していない時間も生命活動を継続する。

ユーザーは食事、触れ合い、遊び、生活環境の管理などを通して生命体と生活する。

生命体は共通EGGから、初期生命体「PIX」として誕生する。

PIXはまだ特定の成長系統を持たないLIFEの原初形態であり、成長の過程でEVOLUTION PATCHを適用することによって形態を変化させる。

誕生から一定時間経過すると、ユーザーは複数のEVOLUTION PATCHから1つを選択し、生命体の成長系統を決定する。

その後も生命体との生活を続け、所定の成長条件を満たした個体は、
選択された系統に対応する成体へ成長する。

生命体には有限の寿命が存在する。

寿命を迎えた生命体はデータへ分解され、その一部を次世代の生命体へ継承することができる。

## 2.2 アプリの目的

本アプリでは、単純なキャラクター収集ではなく、一個体のデジタル生命体との生活、成長および別れを体験することを目的とする。

生命体は誕生時点では特定の成長系統へ分岐しておらず、ユーザーが一定期間一緒に生活した後に、EVOLUTION PATCHを通してその個体の成長方向を選択する。

また、成長系統を選択しただけでは必ずしも最終形態まで成長できるとは限らず、日々のお世話と生命体の寿命がその後の成長へ影響する。

世代を重ねることで過去の生命体の特徴が次世代へ残り、ユーザー固有の生命体の履歴が形成されることを目指す。

## 2.3 想定利用形態

- スマートフォンでの日常的な利用
- 1日に複数回、短時間の操作
- アプリを起動していない時間を含むリアルタイム進行
- 長時間の連続プレイを前提としない
- 1個体と一定期間生活する
- 成長の節目でPATCHを適用し、生命体の形態変化を体験する

# 3. スコープ

## 3.1 初期リリース対象

初期リリースでは以下を実装対象とする。

- 共通EGG
- 共通初期生命体 PIX
- EGGからの孵化
- 生命体の命名
- リアルタイム連動
- 自律行動
- 給餌
- 触れ合い
- 遊び
- JUNK DATAの発生
- JUNK DATAの除去
- 自動給餌
- なつき度
- お世話実績
- 寿命
- 通知
- EVOLUTION PATCHによる形態変化
- 成長系統の選択
- BLAZE / FLOW / BLOOMの3系統
- 幼体への形態変化
- 成体への形態変化
- 成体化とLifetime延長の連動
- 自然終了
- 生命維持失敗による生命活動の終了
- データ分解
- 次世代へのデータ継承
- LIFE DATA表示
- ローカルデータ保存

## 3.2 初期リリース対象外

以下は初期リリースでは実装対象外とする。

- 戦闘
- フレンド機能
- SNS機能
- ユーザー間通信
- ユーザーアカウント
- クラウド同期
- バックエンドサーバ
- BLAZE / FLOW / BLOOM以外の成長系統

## 3.3 将来拡張

以下の機能は将来的な追加候補とする。

- 新しい成長系統
- 新しいEVOLUTION PATCH
- Bondによる成長分岐
- Careによる成長分岐
- 育成履歴による成長分岐
- EVOLUTION PATCHを適用しなかった場合の特殊な成長経路
- シークレット形態
- 新しい生命体
- 新しい行動
- 新しい継承要素
- LIFE RECORD
- その他の生命システム

機能追加は、可能な範囲でゲーム世界内の
`SYSTEM PATCH` として表現する。

キャラクターは初期個体PIXに加え、成長・進化・更新を通じて追加できる構造とする。
キャラクター追加時の変更は原則として定義情報、Asset、登場条件、進化経路の登録に限定し、
共通の育成操作、アニメーション再生、永続化処理へ影響させない。

# 4. 機能要件

## 4.1 デジタル生命体

### FR-LIFE-01

システムは、ユーザーが育成するデジタル生命体を1個体保持できること。

### FR-LIFE-02

生命体は、ユーザーからの操作がない場合でも自律的に行動すること。

### FR-LIFE-03

生命体は、形態・状態・時間帯に応じて異なる行動を行うこと。

### FR-LIFE-04

生命体は現実世界の時間経過に応じて状態が変化すること。

### FR-LIFE-05

生命体ごとに有限の寿命を持つこと。

### FR-LIFE-06

生命体は成長段階を持ち、成長段階に応じて外見を変化させることができること。

---

## 4.2 誕生

### FR-BIRTH-01

新しい生命体は、共通EGGから誕生すること。

### FR-BIRTH-02

EGGから誕生する生命体は、共通の初期生命体 PIX であること。

### FR-BIRTH-03

PIXは誕生時点ではBLAZE / FLOW / BLOOMのいずれの成長系統にも属していないこと。

### FR-BIRTH-04

育成中の生命体が存在しない場合、新しい生命体を誕生させることができること。

### FR-BIRTH-05

新しい生命体の誕生時には、共通EGGからPIXが孵化する演出を行えること。

### FR-BIRTH-06

ユーザーは誕生した生命体へ名前を設定できること。

---

## 4.3 給餌

### FR-FOOD-01

生命体は空腹状態を持つこと。

### FR-FOOD-02

空腹状態は現実時間の経過によって変化すること。

### FR-FOOD-03

ユーザーはデジペレットを生命体へ与えられること。

### FR-FOOD-04

デジペレットを与えることで空腹状態が改善すること。

### FR-FOOD-05

ユーザーはデジペレットを所持・消費できること。

### FR-FOOD-06

システムは日単位でユーザーへデジペレットを供給すること。

---

## 4.4 触れ合い・遊び

### FR-CONTACT-01

ユーザーは生命体と触れ合うことができること。

### FR-CONTACT-02

ユーザーは生命体と遊ぶことができること。

### FR-CONTACT-03

触れ合いおよび遊びによって、生命体との関係性が変化すること。

### FR-CONTACT-04

生命体との関係性に応じて、生命体の反応または行動が変化すること。

---

## 4.5 JUNK DATA

### FR-JUNK-01

生命体の生命活動に伴ってJUNK DATAが発生すること。

### FR-JUNK-02

発生したJUNK DATAはデジタル空間上に表示されること。

### FR-JUNK-03

ユーザーはJUNK DATAを除去できること。

### FR-JUNK-04

JUNK DATAの蓄積状態に応じて、生命体またはデジタル空間の表現が変化すること。

### FR-JUNK-05

JUNK DATAの蓄積のみを直接的な生命活動終了の条件としないこと。

### FR-JUNK-06

ユーザーはHOMEに浮遊するJUNKオブジェクトをタップして除去できること。
JUNK指数1～24では1回の操作につき指数を1減少させること。

### FR-JUNK-07

JUNK指数25以上でアプリを起動しHOMEへ遷移する際、システムクリーニングの確認を提示できること。

### FR-JUNK-08

ユーザーはクリーニングを実行するか延期するか選択できること。
延期時はJUNK指数を変更せず育成を継続できること。
実行時はJUNK指数を0へ戻すこと。ただし発生済みのDATA ERRORは解除しないこと。

### FR-JUNK-09

JUNK指数0～100に応じて、オブジェクト、ノイズ、表示乱れ、プロフィール文字化け、キャラクター破損画像、画面亀裂等を段階的に表現できること。
視覚的汚染段階はJUNKの育成上の状態区分とは独立して扱うこと。

### FR-JUNK-10

JUNK指数の除去・変更に応じて、画面演出が最新の汚染段階へ更新されること。
ノイズやJUNKオブジェクトは、LIFEおよび画面操作の妨げにならないこと。

## 4.6 自動給餌

### FR-AUTOFOOD-01

ユーザーは自動給餌機能を利用できること。

### FR-AUTOFOOD-02

自動給餌では、ユーザーが所持しているデジペレットを使用すること。

### FR-AUTOFOOD-03

生命体の状態が所定の条件を満たした場合、ユーザーの操作なしで給餌できること。

---

## 4.7 お世話実績

### FR-CARE-01

システムは、生命体に対して行われた日々のお世話を記録すること。

### FR-CARE-02

お世話実績は生命体の生涯にわたって蓄積されること。

### FR-CARE-03

お世話実績は生命体の寿命に影響すること。

### FR-CARE-04

お世話実績は、生命体が成体へ成長できるかどうかの判定に影響すること。

### FR-CARE-05

お世話実績となる具体的な行動および評価方法は、ゲームシステム仕様で定義すること。

## 4.8 成長・PATCH

### FR-GROWTH-01

生命体は以下の成長段階を持つこと。

1. EGG
2. PIX
3. BLAZE / FLOW / BLOOM系統の幼体
4. 各系統に対応する成体

### FR-GROWTH-02

PIXは、誕生から120時間経過した時点で次の成長段階へ移行するためのEVOLUTION PATCHイベントを発生させること。

### FR-GROWTH-03

DAY 5のEVOLUTION PATCHイベントでは、ユーザーへBLAZE / FLOW / BLOOMの3種類のPATCHを提示すること。

### FR-GROWTH-04

初期リリースでは、DAY 5に提示されるBLAZE / FLOW / BLOOMについて、Bond、Careその他の育成状態による選択制限を設けないこと。

### FR-GROWTH-05

ユーザーはDAY 5に提示されたEVOLUTION PATCHから1種類を選択すること。

### FR-GROWTH-06

ユーザーがEVOLUTION PATCHを選択した場合、選択したEVOLUTION PATCHの確認画面を表示できること。

確認画面では以下の操作を提供すること。

- `APPLY`
- `BACK`

### FR-GROWTH-07

`BACK` を選択した場合、EVOLUTION PATCH選択画面へ戻ること。

### FR-GROWTH-08

`APPLY` を選択した場合、選択したEVOLUTION PATCHを生命体へ適用すること。

### FR-GROWTH-09

DAY 5のEVOLUTION PATCH適用後、PIXは選択したEVOLUTION PATCHに対応する幼体へ形態変化すること。

対応関係は以下とする。

- BLAZE PATCH → BLAZE系統幼体
- FLOW PATCH → FLOW系統幼体
- BLOOM PATCH → BLOOM系統幼体

### FR-GROWTH-10

初期リリースでは、DAY 5のEVOLUTION PATCH適用を通常の成長経路における必須操作とすること。

### FR-GROWTH-11

DAY 5のEVOLUTION PATCHイベントが発生してからEVOLUTION PATCH適用が完了するまで、
ユーザーを通常の育成画面へ遷移させないこと。

### FR-GROWTH-12

DAY 5のEVOLUTION PATCH適用待ち状態であっても、生命体の時間経過を停止しないこと。

### FR-GROWTH-13

EVOLUTION PATCH適用待ち状態でアプリを終了した場合、次回起動時にも未完了のEVOLUTION PATCHイベントを継続すること。

### FR-GROWTH-14

DAY 5で選択された成長系統は、その個体の以後の成長系統として保持すること。

### FR-GROWTH-15

誕生から15日経過した時点で、生命体のLifetime延長判定を行うこと。

### FR-GROWTH-16

DAY 15のLifetime延長に成功した個体のみ、成体へ成長できること。

### FR-GROWTH-17

DAY 15のLifetime延長に成功した場合、選択済みの成長系統に対応する新しいEVOLUTION PATCHを利用可能にすること。

### FR-GROWTH-18

DAY 15では成長系統を再選択させず、DAY 5で選択した系統に対応する成体EVOLUTION PATCHのみを使用すること。

### FR-GROWTH-19

DAY 15の成体EVOLUTION PATCHが利用可能になった場合、以下を表示すること。

`NEW PATCH DETECTED`

### FR-GROWTH-20

DAY 15のPATCH画面では、以下の操作のみを提供すること。

`APPLY PATCH`

### FR-GROWTH-21

DAY 15のEVOLUTION PATCH画面では、EVOLUTION PATCH適用を回避するための`BACK`、`CANCEL`、`LATER` 等の選択肢を提供しないこと。

### FR-GROWTH-22

ユーザーが `APPLY PATCH` を実行した場合、EVOLUTION PATCH適用中であることを以下の表示によって表現すること。

`PATCHING...`

### FR-GROWTH-23

DAY 15のEVOLUTION PATCH適用完了後、生命体を選択済み系統に対応する成体へ形態変化させること。

### FR-GROWTH-24

DAY 15の成体EVOLUTION PATCH適用が完了するまで、ユーザーを通常の育成画面へ遷移させないこと。

### FR-GROWTH-25

DAY 15のEVOLUTION PATCH適用待ち状態であっても、生命体の時間経過を停止しないこと。

### FR-GROWTH-26

DAY 15のEVOLUTION PATCH適用待ち状態でアプリを終了した場合、次回起動時にも未完了のEVOLUTION PATCHイベントを継続すること。

### FR-GROWTH-27

DAY 15のLifetime延長に失敗した個体については、成体PATCHを利用可能にしないこと。

### FR-GROWTH-28

DAY 15のLifetime延長に失敗し、Lifetimeへ到達した個体は自然終了として扱うこと。

### FR-GROWTH-29

EVOLUTION PATCHによる形態変化後は、現在の形態に応じた外見・基本情報・行動特性を生命体へ反映できること。

## 4.9 寿命・生命活動の終了

### FR-DEATH-01

生命体は有限の寿命を持つこと。

### FR-DEATH-02

生命体の寿命は、お世話実績によって変化すること。

### FR-DEATH-03

生命体が寿命へ到達した場合、自然終了として扱うこと。

### FR-DEATH-04

生命維持に必要な条件を長期間満たさなかった場合、寿命とは別に生命活動を終了することがあること。

### FR-DEATH-05

生命活動終了後、生命体を通常の育成状態へ戻せないこと。

### FR-DEATH-06

生命反応が失われた場合、システムは `LIFE SIGNAL LOST` を表示すること。

### FR-DEATH-07

誕生から15日経過した時点でLifetime延長条件を満たした場合、生命体のLifetimeを延長できること。

### FR-DEATH-08

誕生から15日経過した時点でLifetime延長条件を満たさず、現在のLifetimeへ到達した場合、生命体を自然終了として扱うこと。

## 4.10 データ分解・継承

### FR-INHERIT-01

生命活動を終了した生命体は、データ分解処理の対象となること。

### FR-INHERIT-02

寿命を迎えて生命活動を終了した生命体から、次世代へ継承可能なデータを生成できること。

### FR-INHERIT-03

生命維持失敗によって生命活動を終了した場合、次世代へのデータ継承を行えないこと。

### FR-INHERIT-04

継承によって前世代と完全に同一の生命体を再生成しないこと。

### FR-INHERIT-05

継承された生命体には、
前世代の特徴または性質の一部が反映されること。

---

### FR-DATA-03

育成画面では常時パラメータ値を表示せず、生命体の行動や演出から状態を認識できること。

### FR-DATA-04

生命体の形態変化後は、現在の形態に対応する情報をLIFE DATAへ反映できること。

### FR-NOTIFY-02

### FR-NOTIFY-03

## 4.13 データ保存

### FR-SAVE-01

生命体の状態を端末内へ保存できること。

### FR-SAVE-02

アプリを終了した後も育成状態が保持されること。

### FR-SAVE-03

アプリを起動していない期間についても、経過時間を生命体の状態へ反映できること。

### FR-SAVE-04

生命体の現在の成長段階および選択済み成長系統を保存できること。

## 4.14 キャラクター追加・拡張性要件

キャラクター固有の外見、性格、生活リズム、固有行動、アニメーション等の詳細は `02_CHARACTER.md` で定義する。

以下の要件はキャラクターの種類に依存しない共通機構に適用する。
キャラクター固有のモーション順序・フレーム数等は共通エンジンの固定値としない。

### FR-CHAR-EXT-01｜キャラクターの識別

各キャラクターは一意の`characterId`で識別し、個体の`individualId`とは独立して管理できること。

### FR-CHAR-EXT-02｜キャラクター定義の登録

基本プロフィール、活動設定、利用可能なモーションをキャラクター定義として登録・参照できること。

### FR-CHAR-EXT-03｜共通の育成操作

FOOD、TOUCH、PLAY等の育成操作はキャラクター種別に依存せず利用でき、ゲームルールに従って結果を判定すること。

### FR-CHAR-EXT-04｜共通アニメーション再生

フレーム画像、表示間隔、ループ回数および完了条件をキャラクター定義から取得し、共通処理で再生できること。

### FR-CHAR-EXT-05｜動作シーケンス

待機、移動準備、座標移動、食事等の複数段階の動作を、定義された順序と切替条件に従って再生できること。

### FR-CHAR-EXT-06｜未実装モーションの扱い

対象モーションが未登録・未実装の場合は明示された代替表示へ切り替え、操作自体を不当に無効化しないこと。

### FR-CHAR-EXT-07｜成長と進化

進化先の`characterId`は進化経路の定義から解決し、既存の成長タイミングと判定条件を維持できること。

### FR-CHAR-EXT-08｜初期個体

初期誕生時のキャラクター選択は初期個体定義を参照し、画面各所へのIDの直書きを避けること。

# 5. 画面要件

初期リリースでは、少なくとも以下の画面または表示状態を提供する。

### UI-01 起動

アプリ起動および生命データ読み込みを表現すること。

### UI-02 NEW LIFE

育成中の生命体が存在しない場合、共通EGGから新しい生命体との接続を開始できること。

この画面では成長系統の選択を行わない。

### UI-03 孵化・命名

共通EGGからPIXが誕生する演出を行い、誕生した生命体へ名前を設定できること。

### UI-04 育成

生命体およびデジタル空間を表示し、基本的なお世話操作を行えること。

### UI-05 LIFE DATA

現在の生命体に関する情報を確認できること。

### UI-06 DAY 5 EVOLUTION PATCH選択

誕生から120時間経過した生命体に対して、BLAZE / FLOW / BLOOMのEVOLUTION PATCHを提示すること。

ユーザーがEVOLUTION PATCHを適用するまで、通常の育成画面へ遷移させないこと。

### UI-07 DAY 5 EVOLUTION PATCH確認

選択したEVOLUTION PATCHについて、以下の形式で適用確認を行えること。

```text
BLAZE PATCH

APPLY THIS PATCH?

[APPLY]
[BACK]
```

FLOW / BLOOMについても同様とする。

### UI-08 EVOLUTION PATCH適用

EVOLUTION PATCH適用中であることを演出によって表現し、適用完了後に生命体の形態を変化させること。

### UI-09 DAY 15 PATCH

DAY 15のLifetime延長に成功した個体について、成体化のためのPATCHを提示すること。

表示は以下を基本とする。

```text
NEW PATCH DETECTED

[APPLY PATCH]
```

ユーザーが `APPLY PATCH` を実行した場合、以下を表示すること。

```text
PATCHING...
```

PATCH適用完了後、生命体を選択済み系統に対応する成体へ変化させること。

### UI-10 LIFE SIGNAL LOST

生命活動の終了をユーザーへ通知すること。

### UI-11 データ分解・継承

生命体のデータ分解および次世代への移行を表現すること。

具体的なレイアウトおよび画面遷移は `04_UI_FLOW.md` で定義する。

# 6. 非機能要件

## 6.1 対応環境

### NFR-PLATFORM-01

スマートフォン上で動作するアプリケーションとして提供すること。

対象OSおよび対応バージョンは別途決定する。

## 6.2 オフライン動作

### NFR-OFFLINE-01

初期リリースの基本的な育成機能は、バックエンドサーバへの常時接続を必要としないこと。

## 6.3 データ永続化

### NFR-DATA-01

アプリを終了しても生命体の状態が失われないこと。

### NFR-DATA-02

PATCHイベントの途中でアプリを終了した場合でも、次回起動時にイベント状態を復元できること。

## 6.4 時刻連動

### NFR-TIME-01

アプリが起動していない場合でも、次回起動時に実際の経過時間を反映できること。

### NFR-TIME-02

端末の時刻・タイムゾーン変更等について、生命体の状態に重大な不整合が発生しないよう考慮すること。

### NFR-TIME-03

PATCHイベント等によって通常の育成画面への遷移が制限されている場合でも、生命体内部の時間経過を停止しないこと。

## 6.5 操作性

### NFR-UX-01

日常的なお世話を短時間で実行できること。

### NFR-UX-02

生命体の状態を、数値表示だけに依存せず、行動・アニメーション・デジタル空間の変化から認識できること。

### NFR-UX-03

生命体の重要な成長イベントについては、ユーザー自身の操作によってPATCHを適用する体験を提供すること。

## 6.6 通知

### NFR-NOTIFY-01

ユーザーが通知を許可していない場合でも、基本的な育成機能を利用できること。

## 6.7 拡張性・互換性

### NFR-EXT-01｜追加容易性

新キャラクターの追加で既存のアニメーション再生エンジン、育成サービス、画面側の種別分岐を原則変更しないこと。

### NFR-EXT-02｜責務分離

キャラクター固有データ、共通ゲームロジック、アニメーション再生および画面表示の責務を分離すること。

### NFR-EXT-03｜互換性

既存セーブデータのキャラクターID、個体ID、成長段階、進化経路を保ち、旧定義も安全に読み込めること。

### NFR-EXT-04｜テスト容易性

フレーム設定と再生シーケンスを実画像描画に過度に依存せず自動テストできること。

### NFR-EXT-05｜変更の局所性

キャラクター固有の調整が他キャラクターへ波及しないよう依存を局所化すること。

## 6.8 プライバシー

### NFR-PRIVACY-01

初期リリースでは、
生命体の育成に不要な個人情報を収集しないこと。

# 7. 制約事項

初期リリースでは以下を基本方針とする。

- バックエンドサーバを必須としない
- 生命体データは端末内で管理する
- 常時インターネット接続を前提としない
- 1ユーザーにつき同時に育成する生命体は1個体とする
- 新しい生命体は共通EGGからPIXとして誕生する
- 誕生時には成長系統を選択しない
- DAY 5の成長系統はBLAZE / FLOW / BLOOMの3種類とする
- DAY 5のPATCH適用を通常の成長経路では必須とする
- DAY 5ではユーザー自身が成長系統を選択する
- 初期リリースではDAY 5のPATCH選択にBond等の条件を使用しない
- DAY 15では成長系統を再選択しない
- DAY 15のLifetime延長に成功した個体のみ成体化できる
- PATCH適用待ちによって生命体の時間経過を停止しない
- 詳細なゲームバランス値は本書では定義しない

# 8. 用語定義

| 用語 | 定義 |
|---|---|
| Bond | ユーザーと生命体の現在の関係性 |
| Care | 生命体に対するお世話履歴 |
| PIX | 共通EGG内部のデータが集合・安定化することで形成される、まだ特定の成長系統を持たないLIFEの原初形態 |
| EVOLUTION PATCH | 生命体またはシステムへデータを適用し、状態・形態・機能等を変化させる仕組み |
| BLAZE PATCH | PIXをBLAZE系統の幼体へ変化させるDAY 5のPATCH |
| FLOW PATCH | PIXをFLOW系統の幼体へ変化させるDAY 5のPATCH |
| BLOOM PATCH | PIXをBLOOM系統の幼体へ変化させるDAY 5のPATCH |
| 成体PATCH | DAY 15のLifetime延長に成功した生命体を、選択済み系統の成体へ変化させるPATCH |
| PATCH EVENT | 成長等に伴ってユーザーへPATCHの選択または適用を要求するイベント |
| JUNK DATA | 生命活動に伴って発生する不要データ |
| LIFE DATA | 現在の生命体に関する情報 |
| LIFE SIGNAL LOST | 生命反応が失われたことを示すシステム表示 |
| Lifetime | 生命体が生存できる期間 |
| MEMORY DATA | 生命活動が自然終了した生命体から回収される継承可能なデータ |
| SYSTEM PATCH | アプリの機能追加を世界観内で表現する仕組み |
| 成長系統 | DAY 5のPATCH選択によって決定されるBLAZE / FLOW / BLOOMの成長方向 |
| 初期形態 | 共通EGGから誕生したPIXの形態 |
| 幼体 | DAY 5のPATCH適用後から成体化までの形態 |
| 成体 | DAY 15のLifetime延長に成功した個体が成体PATCHを適用した後の形態 |
| 形態変化 | PATCH等によって生命体の外見および形態が変化すること |
| 自然終了 | Lifetime到達による生命活動終了 |
| 生命維持失敗 | Hunger等の生命維持条件を満たせなかったことによる生命活動終了 |
| 生命活動終了 | デジタル生命体が活動を終了し、育成不能となった状態 |
| デジタル生命体 | ViBilet内でユーザーが育成する生命体 |
| デジペレット | デジタル生命体へ与える食料データ |
